Recon + Binary Sweep

What happens: Passive recon, active recon, walk the entire app at least once, run a binary sweep for low-hanging fruit. Breadth before depth — document everything, exploit nothing.

Key activities:

  • Subdomain & host enum — subfinder, amass, waybackurls, then httpx to filter for live targets
  • Wayback / archive trawl for old endpoints, deprecated APIs, exposed JS source maps and secrets
  • TLS analysis — testssl.sh for cert chain, weak ciphers, expiry, HSTS
  • Path fuzzing recursively (depth 3): feroxbuster -w common.txt -r -d 3
  • Manual walkthrough — click every link, submit every form, document every parameter and response
  • Quick wins: /robots.txt, /sitemap.xml, /.git/config, /.well-known/, JS source maps
Pitfall: Don't go deep on anything today. If ' triggers a SQL error, write it down and KEEP MOVING. Day 4 is for exploitation.
Output by EOD: complete attack-surface map (every host, page, form, parameter) plus a flagged shortlist of "interesting" leads to revisit.
Day 2
Open Auth Worksheet →

Auth & Authorization + Input Probes

What happens: Run one canary per parameter — if it fires, note it and move on. Focus on authentication mechanisms, authorization boundaries, and the input-validation signals that tell you which Day-4 hunts are worth chasing.

Input probes (drop one of each into every parameter):

' · SQLi signal?
<script>alert(1)</script> · XSS reflection?
; whoami · CMDi signal?
../../../etc/passwd · Path traversal?
{{7*7}} · SSTI signal (result = 49)?
{"$ne": null} · NoSQLi signal?

Auth & access-control checks:

  • Password reset — token entropy, host-header poisoning, race conditions
  • JWTs — decode every token. Check alg, kid, expiry, claim-trust boundaries
  • Role matrix — try every state-changing request as anon, low-priv user, other tenant, admin
  • OAuth flows — state validation, redirect_uri matching, scope creep
  • Session lifecycle — invalidation on logout, fixation, concurrent-session policy
Pitfall: Don't grind brute-force without first checking for rate-limit bypasses (X-Forwarded-For, casing, slash variants). One probe, one note, move on.
Output by EOD: role matrix, list of authenticated endpoints, and the signals worth deep-diving on Day 4 (SQLi here, SSTI there).

File Handling + Client-Side Checks

What happens: File-upload endpoints, path-traversal parameters, CORS policy review, WebSocket origin checks. Also begin mapping business logic — coupon reuse, race windows, negative prices, role escalation via PUT/PATCH.

Key activities:

  • Upload endpoints — probe extension, MIME type, magic bytes, content checks; try double-extensions (.php.jpg), uncommon extensions (.phtml, .php5, .shtml), polyglots
  • Path-typed params (?file=, ?page=, ?id=) — try ../etc/passwd, ..%2fetc%2fpasswd, ....//, null-byte truncation
  • CORS — set Origin: https://attacker.com on every data-returning endpoint; check for reflection, null origin, prefix/suffix bypass (target.com.attacker.com)
  • WebSocket — Burp WebSockets history. Check Origin validation on the upgrade handshake
  • Business logic — coupon reuse, parallel-purchase race, negative quantities, sending money to yourself, role-field tampering
Pitfall: Extension blocklists are bypassable. ".php" being blocked doesn't mean ".phtml", ".php5", magic-byte spoofing, or Content-Type swapping won't slip through.
Output by EOD: upload endpoints with their current restrictions, list of unkeyed/abusable parameters, business-logic anomalies worth chaining on Day 5.

Server-Side Deep Dive

What happens: Return to the leads flagged on Days 2–3 and go full depth. Confirm exploitability, build clean POCs, capture impact. This is where critical findings turn into critical reports.

Key activities:

  • SQLi — confirm injection point → fingerprint DB → enumerate schema → exfiltrate (sqlmap --batch --risk=3 --level=5 only after manual confirmation)
  • CMDi — blind OOB via Burp Collaborator / oastify.com; identify shell user, perms, network reachability for pivot
  • SSRF — hit 169.254.169.254/latest/meta-data/iam/security-credentials/ for AWS, metadata.google.internal for GCP
  • SSTI — fingerprint the engine (Jinja2/Twig/Freemarker) → escape sandbox → RCE chain
  • XXE / Deserialization / Race — pick the highest-impact lead first; bury the lower-value variants

Tools: sqlmap, ysoserial, jwt_tool, Burp Turbo Intruder for races, interactsh / oastify.com for OAST callbacks (no Burp Pro required).

Pitfall: Stop chasing variations once you have a working exploit. Document the POC, write the impact, move to the next lead. Time-box each lead.
Output by EOD: working POCs with reproducible request/response pairs, clear impact statements, screenshots ready for the report.

Client-Side Deep + Close Gaps

What happens: Chain. XSS → cookie steal → IDOR. SSRF → AWS metadata → S3 takeover. Combined impact > sum of parts. Finish outstanding leads, verify reproducibility, prep for write-up.

Key activities:

  • Reproduce every Day-4 finding from a fresh session (clear cookies / new browser profile)
  • Chain XSS+CSRF, SSRF+RCE, prototype-pollution+gadget, IDOR+role-escalation, host-header+password-reset
  • Client-side deep — DOM XSS via prototype pollution, postMessage handlers, stored XSS in profile/comment fields
  • OAuth/OIDC — algorithm-confusion JWT, redirect_uri parser confusion, code/token interception
  • Cache & routing — host-header injection, cache poisoning via unkeyed headers, CDN-level smuggling
  • Final pass — anything from the Day-1 surface map still unexplored?

Tools: Burp DOM Invader (for client-side XSS / proto-pollution gadget detection), jwt_tool for algorithm confusion, Param Miner for cache-poisoning unkeyed-header discovery, manual chained POC HTML.

Pitfall: Don't bury chained findings under their components. A 9.8-CVSS chain is one ticket, not three — write it as one finding with the full attack narrative.
Output by EOD: final shortlist with chained POCs, every finding reproducibility-verified, clean request/response pairs ready for the report.
