Recon + Binary Sweep

Passive recon, active recon, walk the entire app at least once, run a binary sweep for low-hanging fruit. Breadth before depth — document everything, exploit nothing today.

2Passive Recon

No traffic to the target yet. Pull what's already public.

Subdomain enum pipeline (passive)subfinder -d example.com -all -recursive -silent -o /tmp/subs-sub.txt
amass enum -passive -d example.com -silent -o /tmp/subs-amass.txt
sort -u /tmp/subs-sub.txt /tmp/subs-amass.txt > subs.txt
echo "[+] $(wc -l < subs.txt) unique subdomains"
Wayback / archive URL trawlwaybackurls example.com | tee wayback.txt | wc -l
echo example.com | gau --threads 10 --o gau.txt
sort -u wayback.txt gau.txt > all-urls.txt
# Filter for interesting endpoints:
grep -aiE "\.(env|git|sql|bak|config|pem|key)|admin|api|debug" all-urls.txt
GitHub dorking (manual queries)# Run these in github.com search (logged-in account = better results)
"example.com" "password"
"example.com" "api_key"
"example.com" "BEGIN PRIVATE KEY"
org:example "secret"
# Or via gh CLI:
gh search code "example.com password" --limit 50
  • Run subfinder -d <root> -all -recursive for subdomain enumeration
  • Run amass enum -passive -d <root> and merge with subfinder output
  • Pull waybackurls <root> archive for old endpoints, deprecated APIs
  • Run gau --threads 10 <root> (gets URLs from AlienVault, Common Crawl, etc.)
  • GitHub dorking: org:<target> + secrets keywords (password, api_key, BEGIN PRIVATE KEY)
  • Shodan / Censys lookup on the target's ASN / IP range
  • DNS records: dig any, MX, TXT (look for SPF/DMARC, sometimes leaks infrastructure)

3Active Recon

Now we touch the target. Identify live hosts, enumerate paths, fingerprint the stack.

Live host probing + tech detectioncat subs.txt | httpx -title -tech-detect -status-code -ip -threads 50 \
  -o live.txt
# View only 200/302 responses with title:
httpx -l subs.txt -mc 200,301,302 -title -web-server -tech-detect
TLS analysis (testssl.sh)testssl.sh --quiet --color 0 --severity HIGH https://example.com \
  | tee testssl.log
# Bulk over the live host list:
while read host; do testssl.sh --quiet --severity HIGH "$host"; done < live.txt
Path fuzzing (recursive, depth 3)feroxbuster -u https://example.com \
  -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
  -x php,html,json,asp,aspx,bak,old \
  -r -d 3 -t 50 -o ferox.txt
Vhost enumerationffuf -u https://example.com -H "Host: FUZZ.example.com" \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-110000.txt \
  -fs 1234   # filter by size of the default 404 response
Targeted port scannmap -sV -sC -Pn -p 80,443,8080,8443,8000,8888,3000,5000,9000 \
  --script "default,http-enum,http-headers,http-title" \
  -oA nmap-quick example.com
  • Probe live hosts: cat subs.txt | httpx -title -tech-detect -status-code -ip
  • TLS analysis with testssl.sh on every live host (cert chain, weak ciphers, expiry, HSTS)
  • Path fuzzing: feroxbuster -u <host> -w common.txt -r -d 3 -x php,html,json,asp,aspx
  • Vhost enumeration: ffuf -u https://<ip> -H "Host: FUZZ.<root>" -w subdomains.txt
  • Targeted port scan: nmap -sV -sC -p 80,443,8080,8443,8000,8888 <host>
  • Inspect security headers (HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy)
  • Stack fingerprint via Wappalyzer / response headers / cookies (Server, X-Powered-By, JSESSIONID, PHPSESSID)

4Quick Wins / Binary Sweep

Five-minute checks that sometimes reveal critical findings on their own.

Five-minute binary sweep (curl batch)TARGET=https://example.com
for path in /robots.txt /sitemap.xml /sitemap_index.xml \
            /.git/config /.git/HEAD /.env /.env.local \
            /.well-known/security.txt /admin /wp-admin \
            /phpmyadmin /server-status /server-info \
            /.DS_Store /backup.zip /backup.tar.gz; do
  code=$(curl -sk -o /dev/null -w "%{http_code}" "$TARGET$path")
  [ "$code" != "404" ] && echo "$code  $TARGET$path"
done
Dump exposed .git repo# Only if /.git/config returned 200:
git-dumper https://example.com/.git ./dumped-repo
cd dumped-repo && git log --all --oneline
git show HEAD:config-dev.json    # or whatever interesting blobs you find
JS source-map enumeration# Find map files referenced in JS bundles:
curl -s https://example.com | grep -oE 'src="[^"]+\.js"' | \
  sed 's/src="//; s/"$//' | while read js; do
  url="https://example.com/$js.map"
  curl -sk -o /dev/null -w "%{http_code}  $url
" "$url" | grep "^200"
done
Security headers auditcurl -skI https://example.com | grep -iE "^(server|x-|content-security|strict|referrer|cross-origin|permissions)"
# Or use SecurityHeaders.com / mozilla observatory
  • Fetch /robots.txt — note disallowed paths (often interesting)
  • Fetch /sitemap.xml and /sitemap_index.xml
  • Test /.git/config, /.git/HEAD — exposed git repo? (try git-dumper)
  • Test /.env, /.env.local, /.env.production
  • Check /.well-known/ (security.txt, openid-configuration)
  • Backup file probes: .bak, .old, .swp, .zip, .tar.gz on common paths
  • Common admin panels: /admin, /wp-admin, /phpmyadmin, /manager/html, /console
  • Trigger error responses (malformed input, weird URLs) — capture stack traces
  • JS source maps (*.js.map) — often leak full server-side source
  • Quick CORS check: curl -H "Origin: https://evil.com" -I <api> on one or two endpoints

5Manual Walkthrough

Click every link, submit every form, document every parameter. Burp's HTTP history is your map.

  • Burp running with FoxyProxy on; HTTPS cert installed; intercept OFF for the walk
  • Walk the app as an anonymous (logged-out) user — every page, every form
  • Register / log in; walk again as low-priv user
  • Repeat as each role available (editor, manager, admin, second tenant)
  • Submit every form (placeholder data) — note the request method, parameters, response
  • Document every parameter: name, location (URL/body/header/cookie), type, expected format
  • Capture all XHR / fetch endpoints — these are your API attack surface
  • Save Burp project file: <target>-day1-recon.burp
